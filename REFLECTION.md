# Reflection

**Challenges.** The hardest part was making the comparison fair. Each framework commits DOM changes at a different moment (React batches renders, Vue flushes on a microtask, Svelte and Angular schedule asynchronously), so every app exposes an adapter that forces a synchronous commit — `flushSync`, `nextTick`, `flushSync` and `ApplicationRef.tick()` — and one shared harness times and verifies every operation. Per-framework tuning mattered more than expected: removing `React.memo` from React's row component doubled update time and tripled deletion time, because every row re-rendered. Angular needed `trackBy` and `OnPush` rows for the same reason. I suspected Svelte's extra whitespace text nodes were slowing it, but an A/B test showed no measurable difference, because Svelte clones pre-built templates.

**How each approach affected performance.** React's virtual-DOM diff costs JavaScript, but with memoised rows its work is proportional to what changed, and its plain immutable arrays used the least memory (2.0 MB for 1,000 tasks). Vue and Svelte wrap each task in reactive proxies, so creation pays for fine-grained tracking (3.8–4.1 MB) that later makes targeted updates cheap. Angular spent the most script time on first render (143 ms against React's 44 ms), creating a view, change-detection bindings and comment anchors for every row, and used the most memory (4.6 MB).

**Best performers.** React rendered fastest at every size, cold and warm (tying Svelte once; 1,000 tasks: 118 ms cold vs Vue 151, Svelte 177, Angular 228). Updating 50 tasks was close for all four (7–13 ms); Vue led at normal speed and Svelte under 4× CPU throttling, where fine-grained reactivity patches only the changed text nodes. React and Angular deleted fastest, while Svelte was slowest at deletion in every run. Svelte (17 KB gzip) and Vue (27 KB) shipped the smallest bundles. In this workload, implementation discipline mattered as much as framework choice.
